# Студия монтажа (Remotion)

Ролики собираются кодом в папке `studio/` (Remotion 4, React/TypeScript). Агент пишет JSON по сценарию, скрипты считают тайминг и проверяют блок, владелец смотрит в браузере и даёт заметки по таймкодам. Шпаргалка по сценам и командам — `studio/SCENES.md`, пример — `studio/episodes/000/`.

## Когда подходит

- Ведущих в кадре нет или мало: голос задаёт тайминг, на каждую реплику — своя сцена
- Большая часть экрана — фото, карты, инфографика, титры, хроника. Кодом это быстрее и единообразнее, чем руками
- Своя съёмка вставляется клипами (`videoClip`), но отбор дублей и цветокор остаются за человеком
- Попутно студия даёт субтитры SRT, главы, атрибуцию для описания и шаблоны превью
- Где невыгодно: если своей съёмки 60 % и больше, нужна тонкая резка дублей. Тогда Remotion рендерит только графику (ProRes 4444 с альфой), а сборка идёт в обычной монтажке

## Установка

1. Node.js 20+, ffmpeg (`brew install ffmpeg`)
2. `cd studio && npm install`
3. `npm run setup:browser` — скачать браузер для рендера (на macOS копируется в `~/Library/Caches`: папки Desktop/Documents защищены, и helper-процессы браузера оттуда падают)
4. Проверка: `npm run timeline -- 000 && npm run check -- 000 && npm run studio`

Remotion бесплатен для физлиц и компаний до 3 человек; иначе нужна лицензия (remotion.dev/license).

## Как устроено

| Файл | Что это | Кто пишет |
| --- | --- | --- |
| `studio/channel.json` | Имя канала, язык, формат чисел, кавычки, тексты плашки подписки, подписи для описания | Агент при онбординге |
| `studio/episodes/NNN/edit.json` | Настройки, голоса, `hero` | Агент |
| `studio/episodes/NNN/blocks/NN-slug.json` | Монтаж одного блока: реплики, ассеты с лицензиями, сцены, плашки, музыка, главы | Агент по сценарию, правки по заметкам |
| `studio/SCENES.md` | Шпаргалка: формат блока, якоря, параметры и лимиты сцен, команды | Агент, при изменении сцен |
| `studio/episodes/NNN/timeline.json` | Таймлайн в кадрах | `npm run timeline -- NNN` |
| `studio/src/episodes.ts` | Список видео и превью для Studio | `npm run timeline` (генерируется) |
| `studio/episodes/NNN/subtitles-<lang>.srt`, `meta.md`, `description-<lang>.txt` | Субтитры, главы, атрибуция, описание | `npm run meta -- NNN` |
| `studio/public/episodes/NNN/` | Голоса, фото, клипы, музыка (не в git) | скрипты и человек |
| `studio/src/scenes/` | Библиотека сцен | Агент |
| `design-system/tokens.json` | Цвета, стили текста, отступы — их читает `studio/src/theme.ts` | Дизайн канала |

### Поток на одно видео

1. Сценарий с репликами по голосам (`ANNA:` / `MAX:` или один `HOST:`) и разметкой `[VISUAL: …]` ([[wiki/content/script-checklist]])
2. Агент переносит реплики и визуал одного блока в `blocks/NN-slug.json`: тип сцены, ассет, параметры; id с номером блока (`L201`, `S201`); сцена привязывается к реплике якорем (`L205`, `L205:end`, `L205+3.6`). Фото — `npm run find-assets`
3. Озвучка: одна реплика = один файл `voice/Lnn.wav`. Заглушки — `npm run tts:placeholder -- NNN` (macOS), боевой голос — `npm run tts:elevenlabs -- NNN` (`--dry` — сколько знаков уйдёт в API). Оба перегенерируют только изменённые реплики; ответы ElevenLabs кэшируются
4. `npm run timeline -- NNN` измеряет реплики и считает тайминг сцен. Без озвучки длительность оценивается по ~140 слов/мин
5. `npm run check -- NNN N` — сводка блока: заглушки, тексты длиннее лимита, нет файла или лицензии, короткие и застывшие сцены, повторы
6. `npm run render:block -- NNN N` → `npm run qa -- NNN N` — рендер блока и локальная проверка. Агент читает только `out/NNN-bN-qa.md`
7. `npm run studio` — владелец смотрит и пишет заметки («на 0:40 фото держится долго»). `npm run where -- NNN 0:40` даёт сцену и реплику, агент точечно правит JSON блока
8. Финал: `npm run render -- ENNN out/NNN.mp4` → `npm run finalize -- NNN` (−14 LUFS) → `npm run meta -- NNN` → превью `npx remotion still TNNN-A out/thumb-NNN-a.png`

### Сцены

Полный список с параметрами и лимитами — `studio/SCENES.md`. Коротко: `archivePhoto` (Ken Burns, подпись и атрибуция в кадре), `videoClip`, `bigDate`, `stat`, `timeline`, `split`, `map`, `yearStrip`, `network`, `dotGrid`, `quote`, `terminal`, `callout`, `checklist`, `nameGrid`, `priceRange`, `document`, `titleCard`, `placeholder`; плашки `speakerTag` и `subscribe`. Переходы: `fade`, `cut`, `dip`. Музыка автоматически приглушается под речью (`duck`).

Новая сцена: компонент в `src/scenes/`, тип в `src/types.ts`, `case` в `src/Episode.tsx`, лимиты в `scripts/check.ts`, строка в `SCENES.md`. Если в сцене есть моменты по якорям — перевод в кадры в `scripts/build-timeline.ts` (по образцу `map`).

## Правила монтажа

Стартовые правила ([[raw/notes/2026-11-15-kit-defaults]]):

- **Заставка доигрывает** ~4 с без речи: у первой реплики после `titleCard` — `pauseBefore` 3–4 с; `speakerTag` — на следующих кадрах, не поверх заставки
- **Графика с цифрами — без анимированного наезда**: scale на всю сцену перерисовывает текст в каждом кадре, цифры дрожат. Крупность — статичная; короткий «поп» при появлении и Ken Burns по фото допустимы
- **Повторы:** один ассет — ≤ 2 показов на видео, не в соседних сценах; герой (`hero` в `edit.json`) — ≤ 3, каждый раз в новой подаче
- **Одна графика** (тот же тип и те же данные) — один раз; повтор только отсылкой ≤ 5 с
- **Статика:** сцена > 15 с — только со сменой внутри (поэтапные `at`, новый элемент), иначе резать на 2–3 сцены
- **Ориентиры на видео:** средняя сцена 6–7 с; текстовая графика ≤ 35 % хронометража; хроника — 10 % и больше
- **Слова под архивный голос** — поверх хроники (`videoClip` + подпись + звук), а не `quote` на тёмном фоне

`check` проверяет повторы, соседние сцены, статику и три сцены одного типа подряд. Последние ориентиры — для сводки по видео после всех блоков.

## Экономия токенов

Принцип: агент работает с одним блоком и видит только короткие текстовые сводки.

- **Один блок — один JSON — одна сессия.** На старте читать страницу видео, `studio/SCENES.md` и только свой кусок сценария (`sed -n` по строкам блока)
- **Не читать** `timeline.json`, логи рендера и сценарий целиком — вместо этого `where`, `check`, `qa`
- **Правки** — точечные Edit, без перезаписи файла
- **Картинки** смотреть только при находках QA — контакт-лист `out/NNN-bN-sheet.jpg`. Исключение: первый блок с новым типом сцены
- **Механические правки** по заметкам можно отдавать более дешёвой модели
- Ориентир: монтаж блока ~15–20k токенов; видео из 8–10 блоков ~150k, если блоки идут в разных сессиях

## Локальные проверки (ollama, по желанию)

Модель через ollama на `localhost:11434` (`studio/scripts/ollama.ts`, по умолчанию `gemma4:12b-mlx`, другая — `OLLAMA_MODEL=…`). Если ollama не запущен, скрипты пропускают шаг и пишут об этом.

| Команда | Что делает |
| --- | --- |
| `npm run qa -- NNN N` | ffmpeg: чёрный экран > 1 с вне сцен `black`, тишина > 2 с вне `pauseAfter`, громкость. Модель: кадр каждой сцены — заглушка или чёрный кадр. Обрезанный текст модель видит плохо — его ловит `check` |
| `npm run find-assets -- "<что нужно>" --cat "Category:…" --q "…"` | Кандидаты с Wikimedia Commons: только PD/CC0/CC BY/CC BY-SA, лицензия и автор — из Commons API. Модель описывает, что на фото, и ставит оценку 0–5. Без модели — просто список. `--cat` использует Bright Data CLI (`bdata`), если он установлен |
| `npm run find-assets -- --get "File:…" --ep NNN --key имя` | Скачивает файл (до 2560 px) и печатает готовую запись для `assets` |

## Риски

- **YouTube и «массовый контент»:** шаблонная сборка может выглядеть как mass-produced. Митигация: монтажные решения принимает человек, сцены разнообразные, есть своя съёмка, ресёрч с источниками
- **Шаблонность картинки:** одинаковые сцены из видео в видео. Периодически добавлять новые типы сцен и менять подачу
- **Рендер-браузер на macOS:** если рендер падает на `icudtl.dat` — не выполнен `npm run setup:browser`; запасной вариант — системный Google Chrome, но он в 2–3 раза медленнее
