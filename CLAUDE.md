# База знаний и студия канала — LLM Wiki + Remotion

## Обзор проекта

Шаблон репозитория для YouTube-канала, который ведёт LLM-агент вместе с владельцем. Полный цикл: тренды → банк тем → досье → сценарий → монтаж кодом → упаковка → публикация → аналитика.

Репозиторий — одновременно:

- **База знаний** (Obsidian vault в `docs/`): идентичность канала, аудитория, банк тем, досье, журнал видео, правила работы
- **Студия монтажа** (`studio/`, Remotion): видео собирается из сценария и озвучки, агент пишет JSON, владелец смотрит и даёт заметки

Канал описан в `docs/wiki/identity/channel-concept.md`. **Если там ещё шаблон-заглушка — сначала пройти процесс «0. Онбординг»** (скилл `/onboarding`).

Этот файл — единственный источник истины для структуры и процессов. Правила под конкретный канал (длина видео, язык, тон, формат ведущих) живут в вики и меняются там, а не здесь.

## Слои вики

### Слой 1: Исходные материалы (`docs/raw/`)

- **Неизменяемые** — после добавления файл не редактируется. Исправление — новым файлом
- Именование: `YYYY-MM-DD-краткое-описание.md` (или `.png`, `.pdf`)
- Каждый файл содержит frontmatter с полями `source`, `date`, `tags` (шаблон `docs/templates/raw-template.md`)
- **Решение владельца — тоже raw.** Сказал «видео не длиннее 15 минут» или «так больше не делаем» — агент записывает это в `raw/notes/YYYY-MM-DD-decision-<тема>.md` и только потом меняет вики. Так у каждого правила есть источник и дата

### Слой 2: Вики-страницы (`docs/wiki/`)

- **Генерируются и обновляются LLM** на основе материалов из `raw/`
- Именование: `kebab-case.md`
- Каждая страница ссылается на исходники через `[[wikilinks]]`
- Страницы можно пересоздать заново из raw-материалов

### Схема (этот файл — `CLAUDE.md`)

- Определяет соглашения, рабочие процессы и правила
- Меняется, только когда меняется структура или процесс, — с записью в `log.md`

## Соглашения для вики-страниц

### Frontmatter (обязательный)

```yaml
---
title: "Название страницы"
category: identity | positioning | audience | content | platforms | competitors | metrics | goals | topics | research | videos
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources:
  - "[[raw/path-to-source]]"
tags:
  - тег1
status: draft | active | archived
---
```

### Правила оформления

- Заголовок H1 (`#`) — ровно один, совпадает с `title` во frontmatter
- Секции — H2 (`##`) и H3 (`###`)
- Ссылки на другие вики-страницы: `[[wiki/category/page-name]]`
- Ссылки на исходники: `[[raw/subfolder/filename]]`
- Списки — маркированные (`-`), нумерованные только для шагов
- Даты — формат `YYYY-MM-DD`
- Язык вики — русский (английские термины без перевода допустимы). Язык видео — свой у канала (`studio/channel.json → language`)

### Именование файлов

- Только латиница, `kebab-case`, без пробелов и заглавных букв
- Категория отражена в папке, не в имени файла
- Видео: `videos/NNN-kebab-slug.md` (порядковый номер, например `001-first-story.md`). Досье в `research/` называется так же, как тема: `first-story.md`. Монтаж — `studio/episodes/NNN/`

## Рабочие процессы

### 0. Онбординг (один раз, скилл `/onboarding`)

1. Агент расспрашивает владельца: о чём канал, для кого, язык видео, длина и частота выпусков, формат подачи (один ведущий / два / закадровый голос), чем канал отличается, 3–10 каналов-ориентиров, 5–10 первых идей
2. Ответы — в `raw/notes/YYYY-MM-DD-onboarding.md` (дословно, без пересказа)
3. Агент заполняет `wiki/identity/channel-concept.md`, `wiki/audience/`, `wiki/positioning/`, `wiki/competitors/benchmark-channels.md`, первые строки `wiki/topics/topic-bank.md`; переводит их из `draft` в `active`, когда информации хватает
4. `studio/channel.json`: имя, `language`, `locale`, кавычки, тексты плашки подписки и подписей — на языке видео
5. Голоса в `studio/episodes/000/edit.json` (пример) и в шаблоне видео — под формат канала
6. Стартовые правила в `wiki/content/` сверяются с ответами: что не подходит каналу — правится со ссылкой на онбординг
7. Запись `ingest` в `log.md`

### 1. Ingest (загрузка исходника)

1. Пользователь добавляет файл в `docs/raw/<подпапка>/` (или агент сам сохраняет туда найденное в ресёрче)
2. LLM читает файл, извлекает ключевые идеи
3. LLM создаёт или обновляет соответствующие вики-страницы в `docs/wiki/`
4. LLM обновляет `docs/wiki/index.md` — добавляет новые страницы
5. LLM добавляет запись в `docs/wiki/log.md`

**Формат записи в лог:**

```
## YYYY-MM-DD HH:MM — ingest
- **Источник:** [[raw/subfolder/filename]]
- **Действия:** создана страница [[wiki/category/page]], обновлена [[wiki/category/other-page]]
- **Итого:** X новых страниц, Y обновлённых
```

### 1a. Weekly trends ingest (если подключён n8n)

1. По понедельникам n8n коммитит `docs/raw/trends/YYYY-MM-DD-trends.md`; перед работой — `git pull`
2. LLM разбирает outlier-видео и комментарии зрителей, отбирает идеи под нишу канала
3. LLM добавляет/обновляет строки в [[wiki/topics/topic-bank]] (тема, угол, потенциал, источник-сигнал) — в таблицу своей рубрики
4. При заметных изменениях у конкурентов — обновляет [[wiki/competitors/benchmark-channels]]
5. Запись `ingest` в `log.md`

Ежедневные снимки `docs/raw/stats/` в вики не переносятся по одному: они нужны для метрик 48ч/7д на странице видео и для периодических сводок в `metrics/`.

### 1b. Video cycle (одно видео, скилл `/new-video`)

1. Тема из банка → статус `в работе`, создаётся страница `videos/NNN-slug.md` по шаблону `templates/video-template.md`
2. Угол + 3–5 заголовков + идея превью. Если упаковка не придумывается — тема слабая, вернуть в банк ([[wiki/content/packaging]])
3. Досье `research/slug.md` по шаблону `templates/dossier-template.md`: каждый факт со ссылкой; найденное в сети — сначала в `raw/references/`
4. Сценарий на языке канала (черновик LLM, вычитка владельцем или носителем) — отдельным файлом рядом со страницей видео (`videos/NNN-slug-script.md`). Перед черновиком и после — памятка [[wiki/content/script-checklist]]; отступления от неё — в «Заметках» сценария
5. Таблица визуала и лицензий заполняется в странице видео ([[wiki/content/visual-licensing-policy]])
5a. Монтаж по блокам (скилл `/edit-block`): блок сценария → `studio/episodes/NNN/blocks/NN-slug.json` → `check` → `render:block` → `qa`; владелец смотрит в Remotion Studio и даёт заметки по таймкодам ([[wiki/content/editing-studio]])
5b. Перед публикацией — чеклист [[wiki/content/publish-checklist]]: его копия лежит в разделе «Публикация» страницы видео, галочки ставятся там
6. После публикации — метрики через 48ч и 7 дней, выводы → в банк тем и в [[wiki/content/script-structure]]

### 2. Query (запрос)

1. Пользователь задаёт вопрос по каналу
2. LLM ищет релевантные вики-страницы и исходники
3. LLM отвечает со ссылками на вики-страницы
4. Если обнаружены пробелы — LLM отмечает их в ответе

### 3. Lint (проверка целостности, скилл `/wiki-lint`)

1. LLM проверяет все вики-страницы:
   - Frontmatter заполнен корректно, H1 = `title`, `category` = папка
   - Все `[[wikilinks]]` ведут на существующие файлы
   - Каждая страница указана в `index.md`
   - Нет дублирования между страницами
   - Статус страниц актуален
2. LLM создаёт отчёт и записывает в `log.md`

**Формат записи в лог:**

```
## YYYY-MM-DD HH:MM — lint
- **Проверено страниц:** N
- **Проблемы:** список найденных проблем
- **Исправлено:** список внесённых правок
```

### 4. Правка правил (обратная связь владельца)

Владелец недоволен результатом («скучно», «заставка не доиграла», «слишком длинно»):

1. Решение — в `raw/notes/YYYY-MM-DD-decision-<тема>.md` или `raw/notes/YYYY-MM-DD-<видео>-review.md`
2. Правило — в страницу, где его будут искать: монтаж → [[wiki/content/editing-studio]], сценарий → [[wiki/content/script-checklist]], упаковка → [[wiki/content/packaging]]
3. Если правило можно проверить кодом — проверка в `studio/scripts/check.ts`
4. Запись в `log.md`

## Студия монтажа: правила для агента

- **Сначала `studio/SCENES.md`**, а не `src/`. Новая сцена или параметр — обновить и SCENES.md
- **Один блок — одна сессия.** Следующий блок начинать в новой сессии с коротким брифом: номер видео и блока, где сценарий, что уже сделано
- **Не читать** `timeline.json`, логи рендера и сценарий целиком: вместо этого `npm run where`, `check`, `qa` и `sed -n` по строкам своего блока
- **Правки по заметкам** — точечные Edit в JSON блока, без перезаписи файла
- **Картинки смотреть только при находках QA** (контакт-лист `out/NNN-bN-sheet.jpg`) или когда сцена нового типа появляется впервые
- **Заставка доигрывает** ~4 с без речи: у первой реплики после `titleCard` — `pauseBefore` 3–4 с; плашки `speakerTag` — не поверх заставки
- **Графика с цифрами и текстом — без анимированного наезда** (scale на всю сцену заставляет цифры дрожать). Крупность — статичная; Ken Burns по фото — можно
- **Лицензии**: у каждого ассета `license` и `url` (кроме своей съёмки — `license: "own"`). Чужие видео и фото без разрешения не использовать
- Команды и пути — в [[wiki/content/editing-studio]] и `studio/SCENES.md`

## Автоматика (n8n, необязательно)

Workflow лежат в `automation/n8n/` и импортируются в развёрнутый n8n. Они коммитят файлы в GitHub-репозиторий канала:

| Workflow             | Расписание         | Пишет                                        | Telegram |
| -------------------- | ------------------ | -------------------------------------------- | -------- |
| `channel-stats.json` | ежедневно 09:00    | `docs/raw/stats/YYYY-MM-DD-channel-stats.md` | да       |
| `trends.json`        | понедельник 08:00  | `docs/raw/trends/YYYY-MM-DD-trends.md`       | нет      |

Файлы от n8n — обычные raw-исходники. Список каналов-ориентиров — `automation/n8n/channels.json` (при изменении обновить Code-ноду `Channels list` в `trends.json`). Настройка — `automation/n8n/README.md`.

## Правила для LLM

1. **Не изменяй файлы в `raw/`** — это неизменяемый слой
2. **Всегда обновляй `index.md`** при создании или удалении вики-страниц
3. **Всегда пиши в `log.md`** после каждой операции (ingest, lint, правка правил)
4. **Сохраняй ссылки на исходники** — каждый факт в вики должен ссылаться на raw-материал
5. **Не дублируй информацию** — одна тема = одна страница, используй ссылки
6. **Обновляй `updated` в frontmatter** при каждом изменении страницы
7. **Пиши вики на русском**, тексты для зрителя — на языке канала
8. **Используй Obsidian wikilinks** — формат `[[path/to/page]]`, не markdown-ссылки
9. **При конфликте** между raw-источником и вики — приоритет у raw-источника
10. **Статус `draft`** — для новых страниц с недостаточной информацией, переводи в `active`, когда страница полноценна
11. **Решения владельца записывай сразу** (процесс 4) — устное правило, которого нет в репозитории, следующая сессия не узнает
12. **Коммиты** — только по просьбе владельца; секреты (`studio/.env`, ключи API) в git не попадают
